# dexp-dock — экран и подсветка док-станции DEXP GS Slayer Pro

Отдельная программа для Windows: выставляет часы на экране дока и управляет его подсветкой.
Нужен только Python 3.10+ (уже стоит). Никаких сторонних пакетов и драйверов: работа с USB идёт
напрямую через системные `hid.dll` и `setupapi.dll`.

## Запуск

- Окно: двойной клик по `start.bat` (или `py -3 -m dexp_dock`).
- Док подключается кабелем к ПК, мышь стоит в доке. Программа находит его сама и переподключается,
  если вынуть и вставить кабель.
- Заводской `GS_Slayer Pro` лучше закрыть: он опрашивает тот же канал.

### Командная строка

```
py -3 -m dexp_dock list                 # что найдено (для диагностики)
py -3 -m dexp_dock check                # проверка на железе: сырые ответы дока + выставить часы
py -3 -m dexp_dock screen-probe         # подбор формата команды часов (смотреть на экран дока)
py -3 -m dexp_dock sync-time            # выставить часы на экране
py -3 -m dexp_dock read                 # текущая подсветка и индикаторы
py -3 -m dexp_dock light --mode 3 --color #00AAFF --brightness 10 --speed 5
py -3 -m dexp_dock indicator 2 1 4
py -3 -m dexp_dock daemon --interval 60 # фоном держать время на экране точным
py -3 -m dexp_dock dpi-follow           # подсветка дока в цвет DPI мыши (без окна, Ctrl+C — выход)
py -3 -m dexp_dock tray                 # сразу свернуто в трей (то же делает start-tray.bat)
```

### Работа в трее

Программа сидит в области уведомлений. Значок закрашен в тот цвет, которым сейчас светится док (серый, если режим
«в цвет DPI» выключен), а в подсказке видно текущий уровень, например «Уровень DPI: 2 из 2 (2500 DPI)».

- Двойной клик (или левый клик) по значку открывает окно. Правая кнопка — меню: «Открыть окно»,
  «Подсветка в цвет DPI мыши» (галочка), «Запускать вместе с Windows» (галочка), «Выход».
- Крестик и сворачивание **прячут окно в трей**, программа продолжает работать. Совсем закрыть её можно
  только пунктом «Выход»: при этом возвращается прежняя подсветка дока.
- Второй запуск не создаёт копию, а показывает окно уже работающей программы.
- «Запускать вместе с Windows» добавляет одну запись в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`
  (только для вашего пользователя, права администратора не нужны); снятие галочки удаляет её. Запускается
  `dexp_dock_tray.pyw` через `pythonw.exe`, без консольного окна, сразу в трее. Если переустановите Python,
  один раз снимите и снова поставьте галочку.
- Значок сделан напрямую через системные библиотеки (`ctypes`), как и всё остальное, никаких пакетов не нужно.

### Подсветка дока в цвет DPI мыши

Во вкладке «Подсветка дока» есть галочка «Подсветка дока в цвет DPI мыши». Пока она включена, док светится
фиксированным цветом текущего уровня DPI: тем же, что показывает индикатор над колесом мыши и программа
GS Slayer. Число уровней, их DPI и цвета читаются из самой мыши, поэтому правки в GS Slayer (другие цвета,
больше или меньше уровней) отражаются на доке сразу, без настройки здесь. Цвет меняется сразу после нажатия
кнопки DPI. Яркость берётся с ползунка на вкладке. При выключении галочки (или закрытии окна) возвращается
прежняя подсветка. Настройка запоминается: при следующем запуске режим включится сам, как только будет найден док.

- `GS_Slayer Pro` можно не закрывать: режим работает и при открытой, и при закрытой программе. Если программа
  отключит «режим драйвера» (например, при сворачивании в трей), это замечается по застывшему значению после
  нажатия DPI, и рукопожатие повторяется. При выходе донгл остаётся в режиме драйвера, пока программа запущена.
- Если мышь «спит», первый цвет появится после её пробуждения (подвигайте мышь или нажмите DPI), обычно за 2–3 с.
- `"dpi_colors": ["#FF0000", ...]` в `%APPDATA%\dexp-dock\settings.json` — запасная таблица (по одному цвету на
  уровень), она используется только пока профиль мыши прочитать не удалось.

Чтобы часы всегда были точными, положите в автозагрузку (`Win+R` → `shell:startup`) ярлык на
`pyw -3 -m dexp_dock daemon` с рабочей папкой, где лежит эта программа.

Режимы подсветки: 0 выкл, 1 радуга, 2 одноцветное дыхание, 3 фиксированный цвет, 4 неон,
5 радужное дыхание, 6 фиксированная радуга. Индикаторы: 0 выкл, 1 частота опроса, 2 заряд мыши,
3 качество связи, 4 уровень DPI.

## Что выяснилось из заводского софта

Установщик `GS_Slayer Pro_v1.0.2.0` собран на Inno Setup, и в него по ошибке попала вся папка
сборки (`.obj`, `.pdb`, `moc_*.cpp`). Протокол восстановлен по `HIDUsb.dll` и объектным файлам.

- Устройство: VID `0x3554` (CompX), док/донгл PID `0xFB34`/`0xFB35`, проводная мышь `0xFB36`.
  В доке MCU WCH CH32V305.
- Команды идут в коллекцию `MI_01 & COL05`: репорт 17 байт, `[0]=0x08`, `[1]` команда,
  `[5]=0x0A` у команд записи, `[6..15]` данные, `[16] = 0x55 − сумма байтов [0..15]`.
  - `0x18`/`0x19` — декоративная подсветка дока: режим, R, G, B, скорость−1, яркость−1.
  - `0x2C`/`0x2D` — три индикатора дока.
  - `0x02` — «драйвер на ПК запущен»: `[5]=1`, `[6]=1` при запуске, `[6]=0` при выходе (заводская программа
    делает это сама). Без этого донгл отдаёт закешированные значения, а не живое состояние мыши.
  - `0x08` — чтение памяти конфигурации: адрес в `[3:5]`, длина в `[5]`. Адрес `0x0004`, длина 1 — текущий
    уровень DPI (индекс 0…5 в `[6]` ответа); отвечает сам донгл, бит `0x80` в `[5]` (пересылка мыши) он отклоняет.
    Память конфигурации хранит каждое поле с контрольным байтом (`0x55 − сумма`): `0x00` частота опроса (маска,
    `0x40` = 8000 Гц), `0x02` число уровней DPI, `0x04` текущий уровень, `0x0C…` восемь записей DPI
    (код `n` → `(n+1)·50` DPI), `0x2C…` восемь цветов R,G,B; уровень *i* берёт запись *i* и цвет *i*.
  - `0x07` — запись в память конфигурации, так пишет настройки заводская программа (**эта программа конфигурацию
    не пишет**): `08 07 00 <адрес hi> <адрес lo> <длина> <значение> <контрольный байт> … CRC`, донгл отвечает тем же
    пакетом. Примеры: опрос `0x00` (1000 Гц=`01`, 4000=`20`, 8000=`40`), число уровней `0x02`, текущий уровень `0x04`,
    LOD `0x0A`, запись DPI `0x0C+4·i`, переключатели датчика `0xAB`/`0xAF`/`0xB1`/`0xB5`.
  - `0x0A` — самопроизвольные события донгла, `[6]` — маска «что изменилось»: `0x01` DPI, `0x02` частота
    опроса, `0x04` конфигурация, `0x08` цвета DPI, `0x20` светодиодная полоса, `0x40` заряд.
- Экран — коллекция `MI_01 & COL08`, репорт 40 байт: `[0]=0x0A`, `[2]=0x10` (часы), год
  (big endian), месяц, день, часы, минуты, секунды, день недели ISO, `[39] = 0x55 − сумма`.
- **Почему заводской софт не управляет экраном.** Окно экрана (`InputPicA`) — заготовка: обработчик
  кнопки «Импорт» состоит из одной инструкции `ret`, у «Яркости» и «Закрыть экран» обработчиков нет
  вообще. Синхронизация часов написана, но с ошибкой: длина пакета считается через `strlen`, а второй
  байт пакета нулевой, поэтому в устройство уходит 1 байт вместо 40, и часы не выставляются никогда.
  Здесь это исправлено.
- Загрузку картинок/GIF и яркость экрана реализовать не из чего: в заводском софте для них нет ни
  одной команды, а подбирать команды наугад опасно (в названиях есть «стирание чипа»).

Проверено на железе (PID `0xFB34`, 2026-09-20): чтение подсветки дока работает, контрольная
сумма совпадает. Индикаторы этот док не поддерживает (отвечает статусом `[2]=1`). Пакет часов
в формате заводского кода док принимает, но время не меняет — формат подбирается через
`screen-probe`.

Запись подсветки (`light`) на железе ещё не проверялась. Если что-то не работает,
запустите `py -3 -m dexp_dock check` и пришлите весь вывод и файл `dexp-dock.log` из папки программы:
в него пишется каждый обмен с доком, а если проверка зависнет дольше 20 секунд, туда же попадёт
место зависания.

```
py -3 -m unittest discover -s tests -t .
```

Тексты интерфейса — в `dexp_dock/locales/ru.json` и `en.json`, в коде только ключи.
